# ADR 0014: Post-1.0 resumable release checklist

## Status

Accepted

## Context

The 1.0 release required repeated reconstruction of state from local evidence, issue
comments, workflows, and human memory. Its immutable candidates exposed that raw
acceptance evidence, platform byte translation, clean-runner behavior, and package-index
dependency resolution require objective checks before a human gate. Post-1.0 releases
need a bounded, repository-owned process without granting automation release authority.

## Decision

Adopt a versioned local checklist runner with external canonical evidence and explicit
read-only forge validation. The release lifecycle is: freeze `develop`, cut a temporary
release branch, review and merge to `main`, verify the exact merge commit, create and
dereference an annotated immutable tag, back-merge `main` to `develop`, verify that
merge, and delete the release branch. The runner prepares and verifies each boundary;
only an authorized human may perform protected-ref, environment, registry, or GitHub
Release actions.

Permanent records are compact manifests and immutable links. Full corpus outputs and
generated review artifacts remain local or retention-bounded workflow artifacts. A
failed candidate or published artifact is replaced by a new version; tags and registry
files are never moved, reused, or rebuilt as substitutes.

## Consequences

Release preparation becomes resumable and auditable without making a coding agent or
conversation part of the control plane. It adds maintained schema, workflow rehearsal,
external evidence storage, and a concise GitHub issue record. Hosted workflows remain
the authoritative artifact producer and exercise the supported operating-system/Python
matrix; full corpus work is release-triggered or scheduled, not per-commit.

## Alternatives considered

Manual runbooks leave objective invariants and recovery state distributed across tools.
Committing generated corpus paperwork creates an unnecessary public archive. A runner
that merges, tags, approves environments, or publishes would weaken the required human
authority boundary. These alternatives are rejected.
